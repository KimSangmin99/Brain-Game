# Brain Lab

게임과 학습 도구를 결합한 한국어 두뇌 연구소입니다. 제품 방향과 상세 명세는 [기획 문서](docs/planning/README.md), 선택한 A 디자인 기준은 [디자인 문서](docs/design-system.md)를 참고하세요.

## 현재 구현

- A 디자인 ‘오늘의 한 걸음’: 밝은 아이보리·녹색, 큰 글자, 단일 시작·이어하기 버튼, 반응형 홈·게임 목록·안내·플레이·결과·기록·계정.
- 전체 8종의 분야 필터와 준비 상태, 게임별 독립 진행. 글자 확대 설정·키보드 탐색·플레이 집중 화면.
- 패턴 복원: 6개 난이도 구간·30단계 파라미터, 조작 연습, 5문항 도전, 정확한 집합 판정, 힌트와 해설, 4/5 통과, 다음 단계 개방.
- 시퀀스 기억: 30단계 파라미터, 도형의 제시 순서 기억, 순서 입력·되돌리기, 키보드 조작, 힌트·정답 비교·다음 단계 개방.
- IndexedDB 게스트 저장: 결과·진행·도움 여부, 새로고침 복구, 중단 문항 교체, 중복 기록 방지.
- 자유 연습과 스테이지 기록 구분, 로컬 기록 목록, 키보드 선택·모바일 조작.
- Vercel 설정과 Supabase PostgreSQL 연결 모듈, 비공개 스키마의 테이블 10개·마이그레이션. 게임별 진행도와 기존 패턴 기록을 보존한다.

- ID·비밀번호 회원가입·로그인·로그아웃, Argon2id 해시, 서버 세션·로그인 제한.
- 완료 기록의 계정 저장·다른 기기 조회, 동의 후 게스트 기록 가져오기, 계정별 로컬 저장 분리.

현재는 두 기억력 게임과 기본 계정을 사용할 수 있는 개발 중 버전입니다. 각 30단계는 난이도 파라미터와 문제 생성으로 구성했으며, 단계별 교육 콘텐츠·대체 문제 전수 검수를 마친 상태가 아닙니다. 나머지 6종, 복구 이메일·비밀번호 재설정·자동 탈퇴, 공식 경쟁은 구현 전입니다. 클라이언트의 게스트 점수는 공식 검증 기록이 아닙니다. 사용자는 Vercel 배포·Supabase 초기 SQL 적용과 환경변수 연결을 완료했습니다. 이번 계정 기능은 추가 SQL 적용과 배포 후 운영 환경에서 검증해야 합니다.

## 실행

Node.js 24 LTS와 npm이 필요합니다. 게스트 플레이는 외부 DB 없이 실행할 수 있습니다. 계정 기능은 DATABASE_URL과 최신 마이그레이션이 필요합니다.

```sh
npm ci
npm run dev
```

개발 서버는 3000번 포트를 사용합니다. 클라우드 작업 환경에서 포트 열기가 제한되어 있으면 해당 환경의 실행 권한 설정을 사용하세요.

```sh
npm run typecheck
npm test
npm run build
npm start
```

## Vercel + Supabase

[연결·배포 안내](docs/deployment.md)에 프로젝트 확인, 서버 환경변수, 마이그레이션과 배포 전 검증 절차를 정리했습니다. ID·비밀번호 인증은 자체 서버 인증으로 구현했으며 Supabase는 PostgreSQL로 사용합니다.

```sh
npm run test:db
npm run db:generate
# 대상 프로젝트 확인과 안전한 DIRECT_DATABASE_URL 설정 후에만 실행
npm run db:migrate
# SQL Editor에서 초기 SQL만 직접 적용한 DB라면 먼저 이력 대조·등록
# npm run db:baseline -- --through=0000
```

마이그레이션은 Vercel 빌드에 포함되지 않습니다. DB 테스트는 로컬 PGlite에서 수행하므로 실제 Supabase 연결·TLS·권한 검증은 별도로 필요합니다.

## 브라우저 검증

```sh
npm run test:e2e
```

Playwright는 `/usr/bin/chromium`을 기본으로 사용합니다. 다른 경로에는 `CHROMIUM_PATH`를 지정합니다. 시스템 Chromium이 없으면 `npx playwright install chromium`으로 설치하고 설치된 실행 파일 경로를 지정하세요. 테스트가 개발 서버를 직접 시작하며, 기존 서버가 있으면 재사용합니다. 브라우저 테스트는 공식 시간 검증이나 실제 모바일 기기 검증을 대신하지 않습니다.

테스트 항목: 5문항 완료·기록 복원·잠금, 입력 제한·중복 제출, 힌트 판정, 중단 복구·새 패턴 교체, 저장 실패, 모바일 조작과 화면 넘침.

## 구조

- `src/lib/pattern.ts`: 게임 상태 전이·판정·파라미터·저장 자료 검증.
- `src/lib/sequence.ts`: 시퀀스 생성·시간별 제시·순서 판정.
- `src/lib/memory-*.ts`, `src/components/use-memory-session.ts`: 공통 결과·게임 어댑터·저장·중단·탭 잠금.
- `src/lib/storage.ts`: IndexedDB 저장과 중복·오래된 쓰기 방지.
- `src/components/pattern-player.tsx`: 제시 시간·입력·피드백·저장 상태.
- `src/components/lab.tsx`: 연구소 홈·목록·진행·기록.
- `src/app`: 페이지·레이아웃·반응형 스타일.
- `src/server`: 계정·세션·요청 검증·기록 병합과 HTTP 처리.
- `src/components/account*.tsx`: 계정 UI와 동기화 상태.
- `src/db`, `drizzle`, `scripts/db-migrate.ts`: 서버 전용 DB 연결·스키마·마이그레이션·제약 검증.
- `e2e`: 실제 브라우저 이용 흐름.

게스트 기록은 이 브라우저에만 보존됩니다. 브라우저 데이터 삭제 시 유실됩니다. 로그인 상태에서는 완료 기록만 서버로 동기화합니다. 진행 중인 문항은 현재 기기에 남습니다. 저장 실패는 화면에 표시하고 로컬 결과를 유지하며 계정 화면에서 재시도할 수 있습니다.
