# 계정 보안·비밀번호·회원 탈퇴

2026-11-13. ID·비밀번호 인증과 개인 기록에 비밀번호 변경, 모든 기기 로그아웃, 비밀번호 재확인을 거친 회원 탈퇴를 추가했다. 선택 복구 이메일과 비밀번호를 잊었을 때의 재설정은 포함하지 않는다. 메일 발송 서비스·발신 도메인·실제 수신 검증이 필요하다. 외부 메일을 보내거나 운영 계정을 삭제하지 않았다.

화면 예시: [PC 비밀번호 변경](security-desktop.png) · [360px 큰 글자 탈퇴 안내](security-mobile.png). 실제 회원이 아닌 로컬 테스트 자료다.

## 사용자 흐름

내 계정 → ‘계정 보안·비밀번호·탈퇴 관리’에서 작업을 고른다. 한 번에 한 양식을 열고 현재 비밀번호를 다시 확인한다. 입력 실패는 해당 양식에 설명하며 비밀번호를 브라우저 저장소에 남기지 않는다.

- 비밀번호 변경: 현재 비밀번호 + 새 비밀번호·확인. 15~128자, 공백·한글·붙여넣기 허용, 가입과 같은 로컬 차단 목록 적용, 현재 비밀번호 재사용 불가. 변경 후 모든 기기의 세션과 기존 인증·복구 토큰을 폐기하고 새 비밀번호로 로그인한다. 완료 기록·진행도·기기의 미전송 기록은 유지한다.
- 모든 기기 로그아웃: 현재 비밀번호를 재확인하고 확정한다. 현재 기기도 로그아웃하며 비밀번호와 개인 기록은 유지한다.
- 회원 탈퇴: 현재 비밀번호 + 로그인 ID 재입력 + 삭제 범위·복구 불가·ID 재사용 불가 확인. 계정과 개인 기록을 운영 DB에서 즉시 삭제한다. 별도의 7일 유예나 취소 기능은 없다. 정책의 ‘7일 이내 삭제’에 해당하는 즉시 처리다.

보안 작업은 계정별 5회/15분, IP별 30회/15분 제한을 공유한다. 성공도 횟수에 포함하며 429에 재시도 안내를 제공한다. 비밀번호 오류는 로그인 세션을 종료시키지 않는다. 실제 세션 만료·계정 변경에 해당하는 오류에서는 세션 상태를 다시 확인한다. 같은 브라우저의 로그인 변경은 저장소 이벤트로 알리고 다른 기기는 다음 접속·요청에서 세션을 검증한다. 브라우저가 오프라인이면 이미 받은 화면·캐시를 원격으로 제거할 수 없다.

## 삭제 범위와 최소 정보

사용자 행 삭제의 외래 키 연쇄로 세션, 인증/복구 토큰, 개인 결과, 진행도, 병합 영수증, 계정에 연결한 메일 대기, 공식 참가 참조를 제거한다. 다른 사용자의 자료와 대회 정의는 남긴다. 공개 공식 경쟁 자체는 현재 미구현이다. 실제 삭제 행을 반환받아 확인하며 트리거가 삭제를 생략하거나 실패하면 삭제 원장도 함께 롤백한다.

`app_private.account_deletions`는 다음 네 값만 보관한다.

| 값 | 목적 |
| --- | --- |
| 무작위 user_id | 백업 복원 시 삭제 목록 재적용 |
| 정규화한 로그인 ID의 SHA-256 | 탈퇴한 ID의 재가입 방지 |
| user_id와 무작위 삭제 확인 UUID를 합친 SHA-256 | 응답 유실 후 삭제 완료 여부 확인 |
| deleted_at | 삭제 처리 시각 |

원장에는 원래 ID·비밀번호·이메일·게임 결과를 저장하지 않는다. ID 해시는 추측 가능한 식별 정보이므로 익명 자료로 표현하지 않는다. 원장은 RLS와 Data API 역할의 접근 회수로 보호하며 회원 API에는 목록·원문을 노출하지 않는다. ID 재사용을 영구 방지하기 위해 원장을 일반 계정 자료와 별도로 유지한다. 로그인 시도 제한의 만료 키는 기존 정리 정책을 따른다.

가입과 탈퇴는 같은 정규화 ID의 트랜잭션 advisory lock을 사용한다. 로그인은 비밀번호 검증 뒤 사용자 행을 잠그고 해시·상태를 다시 확인해 동시에 변경·삭제된 계정에 세션을 발급하지 않는다. 보안 작업도 행 잠금 아래 비밀번호 해시와 현재 세션을 다시 확인한다. 기록 가져오기는 같은 사용자 행을 잠그고 활성 계정을 확인한다.

## 통신 유실과 기기 정리

삭제 요청 전에 브라우저가 무작위 확인 UUID를 만들고 user_id와 함께 보관한다. 비밀번호는 저장하지 않는다. 삭제 원장에 확인 해시를 기록한 뒤 계정을 삭제하는 작업은 하나의 DB 트랜잭션이다. 응답이 유실되면 `POST /auth/deletion-status`로 원래 확인값에 대한 삭제 완료 여부만 조회한다. 이 경로는 삭제를 수행하지 않으며 잘못된 확인값에는 `deleted:false`를 반환한다. 같은 출처 검사, JSON 크기 제한, IP별 조회 제한을 적용한다.

확인된 삭제 후에는 이 계정의 IndexedDB 내용과 동기화/소스 키, 이 계정에 연결된 게스트 원본·병합 표시만 정리한다. 미연결 게스트·다른 계정·큰 글자 설정은 유지한다. 삭제 표시를 먼저 저장하고 저장 직전에도 검사해 오래된 탭이나 진행 중 저장이 기록을 되살리지 않도록 한다. 빈 계정 저장소와 무작위 식별자 기반 삭제 표시는 남을 수 있다. 다른 기기 캐시는 그 기기에서 직접 지워야 한다.

기기 정리가 실패하면 서버 삭제 완료와 기기 정리 실패를 나누어 표시하고 재시도한다. 새로고침 후 로그인되지 않은 상태에서도 남아 있는 확인값으로 이전 탈퇴 요청을 확인할 수 있다. 정리 성공 시 확인값을 제거한다. 보관 중인 확인값은 삭제 상태 조회만 할 수 있고 계정 조작 권한은 없다.

## 배포와 기존 DB 호환

추가 환경변수는 없다. 비밀번호 변경·전체 로그아웃은 기존 0000·0001 SQL로 작동한다. 탈퇴에는 `drizzle/0002_account_deletions.sql`이 필요하다. SQL이 없으면 가입·로그인은 유지하고 탈퇴 버튼을 비활성화한다. DELETE 요청도 설정 오류로 거부하며 데이터는 그대로 보존한다. [배포 안내](../deployment.md)의 계정 관리 항목을 따른다.

수동 SQL 방식은 [계정 관리 업데이트 SQL](../sql/account-management-update.sql)을 한 번 적용한다. 마이그레이션 이력이 이미 있다면 보안 환경변수로 `npm run db:migrate`를 사용한다. 수동 SQL 후에는 현재 구조를 검증하는 `npm run db:baseline -- --through=0002`로 이력을 등록할 수 있다. 기존 이력이 있으면 baseline을 다시 실행하지 않는다. 빌드에서는 마이그레이션을 수행하지 않는다.

## 백업·운영 한계

즉시 삭제는 운영 DB에 적용한다. 과거 백업의 데이터를 자동으로 지우는 기능은 아니다. 삭제 원장을 복원할 백업과 분리된 안전한 위치에 보존하고, 복원 전에 최신 원장을 확보해 복원한 DB에 다시 반영해야 한다. 사용자·세션을 복원한 상태로 서비스를 재개하기 전에 다음 삭제를 트랜잭션으로 적용하고 결과를 확인한다.

```sql
BEGIN;
DELETE FROM app_private.users AS u
USING app_private.account_deletions AS d
WHERE u.id = d.user_id;
COMMIT;
```

이 SQL은 최신 원장이 복구된 상황을 전제로 한다. 오래된 백업에 들어 있는 원장만으로는 이후 탈퇴를 알 수 없다. 백업 보관 기간·외부 원장 보존·복원 재적용·접근 권한의 실제 운영 검증은 아직 완료하지 않았다. 보안 운영 절차와 실제 고지 확정은 출시 전 항목이다. 복원 작업이나 운영 DB 변경을 이 개발 환경에서 실행하지 않았다.

## 검증

단위/DB 테스트는 실제 Argon2id, HTTP 처리 함수와 PGlite로 비밀번호·모든 세션·토큰 폐기·기록 유지, 삭제 범위·타 계정 보존·원장 최소 값·ID 재사용 거부, 인증/동의/동일 출처/요청 제한, 응답 유실 확인, SQL 미적용 호환, 실패·삭제 생략 트리거의 롤백, 중복 삭제와 로그인 경합을 검사한다. 기기 저장 검사는 삭제 범위·재시도·오래된 쓰기 차단을 확인한다.

브라우저 시나리오는 새 비밀번호 재로그인·타 기기 로그아웃, 열린 탭의 세션 갱신, 360px 큰 글자·삭제 확인·다른 기기의 만료·ID 재사용 거부, 삭제 응답 유실과 로컬 저장 실패 후 새로고침 복구, SQL 미적용 시 양식 상태를 검증한다. 이 검사는 운영 Supabase·실제 TLS/풀러·복구 메일 수신·백업 복원·실기기 검증을 대체하지 않는다.
