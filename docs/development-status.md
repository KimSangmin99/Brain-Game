# 개발 진행 기록

## 현재 상태 · 여섯 번째 게임 경로 설계 (2026-11-12)

경로 설계를 추가해 기억 2종·추론 2종·논리 2종, 총 6종을 플레이할 수 있다. 신호 탐색과 룰 스위치는 준비 중이다.

### 구현

- 4/4/5/5/6/6 격자, 필수 지점 0/1/1/2/2/3곳, 21단계부터 방문 순서, 26단계부터 이동 상한의 30단계를 제공한다. 구간 첫 단계는 별도 지도의 조작 예제를 필수로 완료한다.
- 고정 시드 생성기로 단계당 5개·총 150개 지도를 만들고 재방문 없는 모든 도착 경로를 검수했다. 예제 1개를 제외한 4개에서 출제하며 재도전은 직전 지도도 제외한다. 지도·조건·상한·최단 이동 수는 route-content-v1 은행으로 보존한다.
- 칸 클릭·방향키·방향 버튼·한 칸 되돌리기·방문 칸까지 되돌리기·초기화를 구현했다. 잘못된 이동은 확인 횟수를 바꾸지 않고 되돌리기는 재방문 경로를 추가하지 않는다. 출발·도착·지점과 경로는 글자·순번·화살표·색으로 구분한다.
- 연결·지점 누락·순서·상한을 확정 후 설명하고 같은 경로를 수정할 수 있다. 모든 조건을 만족하는 다른 경로도 인정하고, 성공은 8000+floor(2000×L/S)점이다. 최단 이동 수와 제출 이동 수를 결과에서 구분한다.
- 두 단계 힌트, 현재 초안에서 이어갈 수 있는 다음 칸, 풀이 열람 0점·건너뛰기·자유 연습·제출/최단 예시 전환을 제공한다. 실패 피드백·힌트·중단은 독립 해결과 구분한다.
- 같은 지도·초안·제출·조건 피드백·도움을 복구하고 route-v1을 기존 저장·회원 API·게임별 진행에 연결했다. 기존 다섯 게임의 자료와 DB 구조를 유지한다.

### 검증

- TypeScript 검사·프로덕션 빌드, 단위·DB 테스트 89개, 전체 브라우저 시나리오 28개 통과. Node 24·Next·Vitest·Playwright에서 검수 JSON의 모듈 선언과 로딩을 확인했다.
- 독립적인 너비 우선 열거가 150개 지도의 모든 도착 경로 판정과 최단 이동 수를 대조했다. 필수 지점 우회, 자유 방문의 양쪽 순서, 잘못된 지정 순서, 상한 초과와 재방문으로만 가능한 잘못된 해를 검사했다. 생성 과정의 최대 탐색 규모는 지도당 4010노드다.
- 새 브라우저 시나리오 4개는 공개 지도만으로 긴 유효 경로의 점수·단계·기록·홈 이어하기, 모바일 키보드·되돌리기·오류 피드백·힌트·복구, 6×6 큰 글자·순서/상한·풀이 0점, 회원 저장·새 브라우저 조회를 확인한다. 서버는 10000점으로 고정하지 않고 경로 효율 점수를 저장한다.
- 프로덕션에서 실제 게스트 조작과 공개 지도만으로 PC 30단계를 순서대로 해결하고 각 10000점·저장을 확인했다. 대표 1·6·11·16·21·26·30단계는 360·768px, 30단계는 360px 큰 글자로 확인했다. 입력 화면 45개 상태에서 가로 넘침·44px 미만 조작 영역·확정 전 최종 조건 피드백/풀이·브라우저 실행 오류가 없었다. [PC](games/route-desktop.png)·[모바일](games/route-mobile.png) 캡처는 로컬 예시다.
- 계정 검증은 실제 HTTP 처리 함수와 로컬 PGlite를 연결한 테스트다. 운영 Supabase·TLS·풀러·실기기·시니어 사용자 난도·교육 효과 검증을 대체하지 않는다.

[경로 설계 구현 문서](games/route.md)에 지도 검수·판정·점수·복구·콘텐츠 은행의 범위와 제약을 기록했다. 추가 SQL·환경변수는 없다. 기존 계정 업데이트 SQL(0001) 완료에 대한 사용자 확인을 전제로 한다. GitHub main 반영은 연결된 Vercel 자동 배포의 입력이 되며, 이 환경의 외부 운영 URL 접근 제한으로 배포 성공은 직접 검증하지 못한다.

다음 구현 대상은 주의·판단 분야의 신호 탐색이다. 아래 미푸시 표시는 각 구현 단위 작성 당시의 기록이다.

## 현재 상태 · 다섯 번째 게임 조건 배열 (2026-11-12)

다음 구현 단위인 조건 배열을 추가했다. 이제 기억 2종·추론 2종·논리 1종으로 총 5종을 플레이할 수 있다. 경로 설계·신호 탐색·룰 스위치는 준비 중이다.

### 구현

- 3/3/4/4/5/6명과 직접 위치 → 바로 왼쪽 → 순서 → 순서+인접 → 부정 조건 → 전체 혼합의 6구간·30단계를 제공한다. 구간 첫 단계는 실제 배치 조작 예제를 필수로 완료하고 본문항에는 다른 문제를 사용한다.
- 단계별 조건 틀을 3!~6! 전체 배치와 대조한 후 대상 치환으로 문제 은행을 구성한다. 유일한 해, 단계 조건·대상 범위·단서 중복을 검사하며, 인접·새 부정 조건을 제외하면 여러 해가 남도록 학습 조건의 필요성을 확인했다.
- 선택 후 배치·자리 교환·대기 복귀·마우스 드래그·키보드 선택/배치/이동/비우기를 제공한다. 제출 전 정오 노출과 편집 횟수 불이익은 없다.
- 틀린 제출은 배치를 고정해 만족/위반한 조건과 실제 자리 번호를 설명하고 수정으로 돌아간다. 수정 후 해결은 10000점·도움 사용으로 기록한다. 두 단계 힌트·풀이 열람·건너뛰기·자유 연습·결과 풀이를 연결했다.
- 같은 문제·작성 중 배치·마지막 제출·확인 횟수·피드백·도움 이력을 복구한다. arrangement-v1 / arrangement-content-v1을 기존 저장·결과 계산·회원 API에 추가하고 게임별 진행을 분리한다.
- A 디자인에서 PC는 조건과 보드를 나란히 배치하고 보드를 고정한다. 모바일은 조건 → 대상 → 자리 순서로 읽으며 6자리도 한 줄로 유지한다. 이름·모양·색으로 대상을 구분한다.

### 검증

- TypeScript 검사·프로덕션 빌드, 단위·DB 테스트 73개, 전체 브라우저 시나리오 24개 통과.
- 30단계에서 서로 다른 120개 문제를 독립적으로 모든 배치와 비교해 유일한 해를 확인했다. 조건 뜻·복수 해답 검증 예시·새 조건 필요성·교환·수정 후 점수/도움·복구·불일치 기록 거부·기존 네 게임과의 저장 호환을 검사했다.
- 새 브라우저 시나리오 4개는 공개 조건만을 사용해 실제 퍼즐을 풀고, 기록·홈 이어하기·다른 게임 잠금·키보드·드래그 교환·피드백 복구·힌트·6명 큰 글자·풀이 0점·수정 후 회원 저장·다른 브라우저 복원을 확인한다.
- 최초 전체 검사에서 기존 패턴의 노출 후 화면 전환을 기다리는 한 건이 5초 한도를 넘었다. 게임의 3초 노출은 유지하고 테스트 대기를 10초로 늘린 뒤 전체 24개를 재실행해 통과했다.
- 프로덕션에서 공개된 조건만으로 실제 게스트 조작을 통해 PC 30단계 모두를 순서대로 해결하고 각 10000점·저장을 확인했다. 그 로컬 기록으로 대표 1·6·11·16·21·26·30단계를 360·768px에서, 30단계를 360px 큰 글자로 확인했다. 입력 화면 총 45개 상태에서 가로 넘침·44px 미만 조작 영역·제출 전 정오/정답 표시·브라우저 실행 오류가 없었다. [PC](games/arrangement-desktop.png)·[모바일](games/arrangement-mobile.png) 캡처는 로컬 예시다.
- 회원 DB 검증은 실제 HTTP 처리 함수와 로컬 PGlite를 연결한 테스트다. 실제 Supabase·TLS·풀러·시니어 사용자·실기기·학습 효과 검증을 대체하지 않는다.

[조건 배열 구현 문서](games/arrangement.md)에 조건·점수·도움·복구·문제 은행의 범위와 제한을 기록했다. 추가 SQL·환경변수는 없다. 기존 계정 업데이트 SQL(0001) 완료에 대한 사용자 확인을 전제로 한다. GitHub main 반영은 연결된 Vercel 자동 배포의 입력이 되며, 외부 운영 URL 접근 제한으로 이 환경에서 배포 성공은 직접 검증하지 못한다.

## 현재 상태 · 네 번째 게임 코드 브레이커 (2026-11-12)

다음 개발 단위로 코드 브레이커를 추가했다. 사용 가능한 게임은 기억 2종·추론 2종으로 총 4종이며, 조건 배열·경로 설계·신호 탐색·룰 스위치는 준비 중이다. 이 반영 단위에는 이전 규칙 분석의 미푸시 변경도 함께 포함한다.

### 구현

- 명세의 6개 구간·30단계에 맞춰 3~5자리, 4~6종 기호, 중복 허용 조건과 6~10회 추측을 제공한다. 한 코드를 해독하면 통과하며 구간 첫 단계의 단서 예제를 필수로 둔다.
- 위치 일치를 먼저 제외한 뒤 남은 기호를 일대일 대응해 중복 기호를 과대 계산하지 않는다. 모든 추측과 두 단서를 보존하고 앞선 단서와 모순되는 추측은 제출 후 설명한다.
- 칸 선택·수정·숫자/방향 키·지우기, 중복 제출 차단, 전략/후보 힌트, 풀이 열람 종료, 건너뛰기·재도전·자유 연습을 제공한다. 후보는 실제 정답을 조회하지 않고 공개 단서만으로 계산한다.
- 점수는 성공 시 8000~10000점, 실패·풀이 열람·건너뛰기는 0점이다. 한 코드 결과와 추측 횟수를 기존 5문항 게임과 구분해 홈·기록·서버 검증·진행 계산에 연결했다.
- 새로고침·탭 숨김·나가기는 같은 코드·추측 이력·작성 중 조합·도움 이력을 보존하고 중단으로 표시한다. 기존 세 게임의 버전과 저장 구조를 유지하고 code-v1 계정 동기화·새 브라우저 조회를 추가했다.
- A 디자인을 적용했다. 색·기호 모양·이름을 함께 제공하고, 360px 큰 글자에서도 5자리 입력과 6종 기호를 조작할 수 있다.

### 검증

- TypeScript 검사·프로덕션 빌드 통과. 단위·DB 테스트 59개, 전체 브라우저 시나리오 20개 통과.
- 코드 판정은 729개 작은 조합 쌍을 독립 다중집합 계산과 비교하고 30단계 조건·후보 필터·입문 24개 코드의 단서 기반 해독·첫/마지막 점수·소진·부정한 저장 자료 거부·중단·저장 호환을 검사했다.
- 브라우저에서 새 게임 완료·분리된 단계·기록·홈 이어하기, 모바일 키보드·수정·중복 차단·힌트·복구·풀이 열람, 5자리 큰 글자와 계정 저장·다른 브라우저 조회를 확인했다. 첫 브라우저 실행에서 개발 서버의 초기 컴파일 대기와 텍스트 비교 테스트를 조정한 뒤 전체 20개를 다시 통과했다.
- 프로덕션 서버에서 대표 1·5·6·11·16·21·26·30단계를 360·768·1280px, 30단계를 360px 큰 글자로 확인했다. 총 25개 화면에서 가로 넘침·44px 미만 조작 영역·플레이 중 정답 노출·브라우저 실행 오류가 없었다. [PC](games/code-desktop.png)·[모바일](games/code-mobile.png) 캡처는 로컬 예시다.
- 계정 DB 검증은 실제 HTTP 처리 함수와 로컬 PGlite를 연결한 테스트다. 운영 Supabase·TLS·풀러와 실제 시니어 사용자·실기기·교육 효과 검증은 별도다.

[코드 브레이커 구현 문서](games/code.md)에 규칙·점수·복구 계약을 기록했다. 추가 SQL·환경변수는 없다. 기존 계정 업데이트 SQL(0001) 완료에 대한 사용자 확인을 전제로 한다. GitHub main에 반영하면 연결된 Vercel 자동 배포 대상이 되며, 이 환경의 외부 운영 URL 접근 제한으로 배포 성공을 직접 검증하지 못한다. 아래 각 구현 단위의 미푸시 표시는 당시 작성 시점의 기록이다.

## 현재 상태 · 세 번째 게임 규칙 분석 (2026-11-09)

사용자가 계정 업데이트 SQL(0001) 완료를 확인했고, 다음 개발 대상으로 규칙 분석을 지시했다. 이 작업 환경에는 운영 DB 인증이 없어 사용자 확인과 원격 검증은 구분한다. 규칙 분석 추가에는 별도 마이그레이션이 없다.

### 구현 범위

- 추론 분야의 규칙 분석을 플레이 가능하게 열었다. 이제 기억 2종·추론 1종이며 다른 5종은 준비 상태를 유지한다.
- 단일 속성 순환·증감 → 두 속성 독립 → 교대 → 교대와 결합 → 혼합의 30단계와 8개 세부 유형을 제공한다. 방향·표식·개수(1~7)를 그림·이름·숫자로 함께 표시한다.
- 유한 규칙 카탈로그에서 같은 단서에 맞는 모든 모델의 다음 항목이 일치하는 경우만 채택한다. 문제 범위를 표시하고 4개 선택지는 중복·복수 정답을 제외한다. 두 속성 문제는 한 조건 오류·다른 조건 오류·두 조건 오류의 보기를 각각 제공한다.
- 필수 구간 예제·5문항·4/5 통과·수정 가능한 단일 선택·숫자/방향 키·건너뛰기·두 단계 힌트·문항별 해설·결과 회고·자유 연습을 구현했다.
- 공통 게임 세션 어댑터를 확장해 기록 저장·중단 문항 교체·게임별 단계·탭 잠금·회원 기록 동기화에 연결했다. 기존 두 게임의 기록 버전과 IndexedDB 구조는 유지한다. 새 결과는 rule-v1 / rule-content-v1이며 개인 imported/unverified 기록이다.
- 홈은 최근 게임 이어하기와 다른 2게임으로 구성하고 완료 단계 수를 전 게임에서 계산한다. 목록의 사용 가능·준비 중 수와 상세의 단계 목표·조건·기록 아이콘도 새 게임에 맞췄다.
- PC는 단서와 선택지를 비교하기 쉽게 배치하고 단서를 고정한다. 좁은 화면에서는 2열, 큰 글자 선택지는 1열로 늘려 읽는다.

### 검증

- 단위·DB 테스트 47개 통과. 30단계에서 1,500문항의 유효성·유일한 예측·중복 제거를 검사하고, 독립적인 차이 계산으로 다음 항목과 비교했다. 증가/감소 학습 목표, 두 속성 보기의 필요성, 예제와 본문항 분리, 부정한 저장 자료·정오·힌트 이력 거부, 중단 교체와 기존 기록 보존을 확인했다.
- 브라우저 시나리오 16개 통과. 새 게임 완료·단계 개방·홈 이어하기·기억 게임 진행도 분리·모바일 큰 글자·키보드·힌트·복구와 계정 저장·다른 브라우저 조회를 검증했다. 콘텐츠 보강 후 규칙 분석 3개를 다시 확인했다.
- TypeScript 검사와 프로덕션 빌드 통과. 대표 단계 1·7·8·13·16·18·21·30을 360·768·1280px에서, 21단계를 360px 큰 글자로 확인했다. 총 25개 화면에서 가로 넘침·44px 미만 선택지·브라우저 실행 오류 없이 실제 선택·정답 판정이 됐고 PC에서는 단서가 보이는 상태로 답을 비교할 수 있었다.
- 계정 DB 검증은 로컬 PGlite와 실제 HTTP 처리 함수를 연결한 테스트다. 실제 Supabase 연결·TLS·풀러 운영 검증을 대체하지 않는다. 대표 단계 확인의 진행 기록은 로컬 전용 테스트 예시다.

상세 규칙·제약은 [규칙 분석 구현 문서](games/rule.md)를 따른다. 실제 사용자 난도·교육 효과 검증과 장기 반복 노출 제어는 후속 범위다. 이번 코드 변경은 작업 공간에 작성했으며 GitHub 푸시·운영 배포는 수행하지 않았다.

## 현재 상태 · A 디자인 적용 (2026-11-09)

사용자가 세 가지 시안 중 A ‘오늘의 한 걸음’을 선택했다. 밝은 아이보리·녹색, 큰 글자, 한 가지 주 행동, 기억 보드 오브젝트를 중심으로 전체 화면에 적용했다. 이전 계정·기록 개발 변경은 유지했으며 디자인을 위한 DB 변경은 없다.

### 변경 범위

- 홈을 인사·실제 완료 단계 → 시작/최근 게임 이어하기 → 학습 3단계 → 사용 가능한 2종으로 재구성했다. 전체 8종은 별도 게임 목록에서 분야 필터·준비 상태와 확인한다.
- 전체 게임 목록, 상세·스테이지·자유 연습, 두 게임의 안내·문제·힌트·정오 피드백·결과, 기록·빈 상태, 로그인·가입·계정·안내, 준비 중인 챌린지와 오류 화면을 같은 기준으로 구성했다.
- CSS를 공통 토큰과 화면별 배치로 정리했다. 단순 색상 교체가 아니라 홈 정보 구조, 가로형 게임 카드, 큰 단계 카드, 플레이 집중 화면과 기록 행을 적용했다. 게임 규칙·판정·제시 시간·저장·회원 API는 유지했다.
- 큰 글자 설정의 브라우저 유지, Escape 닫기와 열었던 버튼으로 포커스 복귀, 최소 조작 크기·줄바꿈·동작 감소를 적용했다. 플레이에서는 공통 탐색·푸터를 접어 조작을 가리지 않고 결과에서 복원한다.
- 사용자 선택에 맞춰 제품·화면 기획을 갱신하고 [디자인 기준](design-system.md)을 작성했다.

### 검증

- TypeScript 검사와 프로덕션 빌드 통과. 단위·DB 통합 테스트 36개 통과.
- 브라우저 시나리오 13개 통과: 기존 두 게임·회원·기록 흐름, 글자 확대 유지, Escape 포커스 복귀, 플레이 탐색 접기·복원. 이후 홈 단순화에 맞춰 패턴·시퀀스의 실제 다음 단계로 이어지는 경로도 추가 검증했다.
- 프로덕션에서 360·768·1280px, 큰 글자, 200% 확대에 대응하는 640 CSS px 재배치 조건 등 56개 화면 상태를 캡처했다. 가로 넘침·44px 미만의 버튼·브라우저 실행 오류가 없었다. 각 화면을 통한 실제 실기기·스크린리더·시니어 사용자 검증을 대신하지 않는다.
- 별도로 두 게임의 30단계에 도달한 로컬 예시 기록을 만들어 360px·큰 글자에서 5×5 보드 25칸과 도형 버튼 6개의 조작 영역이 44px 이상임을 확인했다.
- 주요 색 조합의 대비: 본문 11.19:1, 보조 설명 5.40:1, 주 버튼 7.62:1, 힌트 5.46:1, 오류 6.61:1. 전체 접근성 적합 판정은 아니다.
- 실제 캡처는 `design-explorations/2026-11-09/implemented/`에 있다. 기록이 채워진 예시는 로컬 테스트 기록이며 실제 회원 개인정보가 아니다.

변경은 현재 작업 공간에 반영했다. 이번 디자인·계정 변경의 GitHub 푸시·운영 배포·Supabase 추가 마이그레이션은 수행하지 않았다. 이전에 안내한 계정 기능 적용 절차는 [배포 안내](deployment.md)를 따른다.

## 현재 상태 · 세 번째 구현 단위 (2026-11-09)

사용자가 Vercel 배포와 Supabase 초기 SQL·환경변수 설정 완료를 확인했다. 이번 단위는 자체 계정과 완료 기록 동기화다. 이 작업 환경에는 운영 DB 자격 증명이 없어 운영 Supabase에 대한 새 SQL 적용과 실서비스 검증은 수행하지 않았다.

### 구현

- ID·비밀번호 회원가입·로그인·로그아웃과 계정 화면. ID 정규화, 15~128자 비밀번호, 소규모 오프라인 취약 비밀번호 차단, 안내 확인 버전·시각 기록.
- Argon2id(64MiB·3회·병렬 1), 256비트 무작위 세션과 DB 해시 저장, 운영 Secure·HttpOnly·SameSite=Lax 쿠키. 미사용 7일/절대 30일 만료·로그인 시 현재 세션 회전·로그아웃 시 서버 폐기.
- 분산 인스턴스 공통 DB 요청 제한, Origin 확인, JSON 용량 제한, 내부 오류·비밀번호 비노출, 개인정보 응답 no-store. 요청 시 예상 계정 ID를 대조해 다른 탭에서 계정이 바뀐 상태의 기록 전송을 차단.
- 계정별 로컬 저장 분리, 완료 결과의 서버 저장·페이지별 조회·다른 기기 복원. 진행 중인 문항은 기기에만 남음. 서버 장애 시 로컬 결과 보존·저장 실패 안내·계정 화면에서 재시도.
- 명시적인 게스트 기록 가져오기. 완료 집합 합집합, 불변 결과·영수증·진행 갱신을 같은 트랜잭션에서 처리하고 교차 계정 재병합 거부. 성공한 게스트 원본은 7일 후 조회 때 정리하고 실패한 원본은 보존.
- 모든 클라이언트 결과를 imported/unverified로 저장하며 공식 경쟁에 사용하지 않음.
- 0001 마이그레이션: auth_limits 테이블과 users 안내 확인 열 2개. 수동 초기 SQL 적용 DB의 구조를 검증한 뒤 Drizzle 이력을 등록하는 db:baseline 명령 추가. 앱 데이터 변경 없이 불일치·권한 차이·기존 이력이 있으면 중단.

### 검증과 제한

단위·PostgreSQL 호환 통합 테스트 36개가 통과했다. 실제 Argon2id 해시, 세션 만료·폐기, CSRF·입력 크기·요청 제한, 계정 분리, 불변 기록·중복 병합·트랜잭션 롤백, 수동 SQL 이력 등록 후 다음 마이그레이션 적용, 게스트 원본 보관·삭제를 검증했다.

브라우저 계정 테스트는 실제 HTTP 처리 함수와 로컬 PGlite DB를 연결하며, Next.js 페이지에서 회원가입·로그인·기록 가져오기·새 브라우저 복원·로그아웃 분리·서버 저장 실패와 재시도를 확인한다. 운영 PostgreSQL 드라이버·TLS·Supabase 풀러 검증을 대체하지 않는다. 기존 두 게임의 브라우저 시나리오 9개와 계정 시나리오 3개가 통과했다. TypeScript 검사·프로덕션 빌드도 통과했으며, 실제 요청 Host와 내부 서버 포트가 다른 경우의 Origin 검사를 회귀 테스트로 추가했다. 프로덕션 서버에서 계정 페이지 HTTP 200, 게스트 세션, 외부 Origin 403, DB 미설정 503과 모바일 초기화·화면 넘침 없음을 확인했다.

복구 이메일·비밀번호 재설정·자동 탈퇴·공식 경쟁·나머지 6종은 후속 범위다. 정식 출시 전 운영자·문의처·보관·삭제 절차가 포함된 이용약관과 개인정보 처리방침을 확정해야 한다. 현재 가입 안내는 개발 중 기능과 수집 범위·제한을 설명한다.

이번 변경은 작업 공간에 작성했다. 기존 운영 배포는 이전 커밋이며 이번 변경의 GitHub 푸시·운영 SQL 적용·Vercel 배포는 수행하지 않았다. 적용 순서는 [배포 안내 7절](deployment.md#7-이번-계정-기능-업데이트-적용)을 따른다.

## 현재 상태 · 두 번째 구현 단위 (2026-11-05)

Vercel + Supabase PostgreSQL을 배포 구성으로 반영했다. 두 기억력 게임과 DB 연결 기반을 구현했으며 실제 서비스 연결은 프로젝트 식별 정보와 실행 환경의 인증 설정을 기다리고 있다. 아래 첫 구현 기록은 당시 상태를 보존한 것이다.

### 구현

- 시퀀스 기억의 6개 난이도 구간·30단계, 도형 제시·순서 입력·되돌리기·키보드·힌트·정답 비교·결과·다음 단계 개방을 추가했다.
- 패턴·시퀀스의 세션 저장·중단 복구·탭 잠금과 결과 계산을 공통화했다. 기존 pattern-v1 IndexedDB 기록을 유지하며 게임별 진행도와 기록을 분리했다. 홈의 이어하기는 최근 게임으로 연결된다.
- 서버 전용 PostgreSQL 연결과 트랜잭션 풀러 옵션, Drizzle 스키마·초기 SQL·별도 마이그레이션 명령을 추가했다. 9개 테이블에 RLS·비공개 스키마 권한을 설정했다.
- Vercel 빌드 설정과 서버 환경변수 예시, [연결·배포 안내](deployment.md)를 작성했다. 기술 설계의 상주 워커 계획을 예약 작업·DB lease 방식으로 변경했다.

### 검증

- TypeScript 검사와 프로덕션 빌드 통과. 프로덕션 서버에서 홈 HTTP 200, 시퀀스 초기화·저장, 최근 게임 이어하기 링크와 브라우저 실행 오류 없음을 확인했다.
- 게임·저장·DB 테스트 24개 통과. DB 검증은 로컬 PGlite에서 마이그레이션 재실행, ID 중복·이메일 상태·공식 중복 참가 제약, Data API 역할 접근 차단과 게임별 진행도를 확인했다.
- Chromium 브라우저 시나리오 9개 통과. 기존 패턴 시나리오 6개와 시퀀스 5문항 완료·기록 재접속·별도 단계 개방, 모바일 키보드·되돌리기·힌트·화면 넘침, 노출 중 새로고침 복구를 검증했다.
- 시퀀스 모바일 캡처를 확인했다. 실제 휴대폰과 시니어 사용자 플레이테스트는 아직 수행하지 않았다.
- 마이그레이션 CLI의 CommonJS 로딩 호환 문제를 수정했다. 자격 증명 없이 실행하면 DB에 접근하지 않고 필요한 환경변수를 안내한다.

### 남은 범위

1. 기존 Vercel·Supabase 프로젝트 확인, 안전한 자격 증명 설정, 원격 마이그레이션과 연결·TLS·권한 검증.

## 구현 범위

기획서 D01 중 프런트엔드 실행 기반과 버전 잠금, D02 패턴 복원용 플레이 상태, D03 게스트 플레이 흐름을 구현했다. D01의 PostgreSQL·마이그레이션은 아직 수행하지 않았다. 전체 개발 범위는 8종을 유지한다.

패턴 복원은 안내·조작 예제·제시·선택·판정·해설·결과·다음 단계로 이어진다. 힌트 사용과 중단 이력을 기록하고, 기존 완료를 보존한다. 단계별 6개 구간의 수치는 기획서와 일치하며 생성된 문제는 세션 안에서 중복되지 않는다.

## 구현상 제한

- 30개 단계의 수치·진행은 제공하지만 단계별 교육 목표에 맞춘 패턴 선정, 전체 대체 문제 풀, 사용자 난도 검증은 남아 있다.
- 자유 연습은 현재 열린 단계의 문제를 반복하는 기능이다. 쉬운 조건을 자동 추천하는 보충 연습과 복습 추천은 후속 구현이다.
- 전략 힌트 1단계를 제공한다. 현재 문제 힌트·풀이 열람은 아직 제공하지 않는다. 정답 제출 후 해설은 구현했다.
- 최근 미완료 시도를 이어가며, 노출 중 복구는 다른 문제로 대체하고 독립 성취에서 제외한다. IndexedDB를 사용할 수 없으면 저장 불가를 표시한다.
- Web Locks 지원 환경에서는 다른 탭의 동시 플레이를 막는다. 미지원 환경에서는 결과 중복·과거 상태 덮어쓰기 방지를 제공하지만 탭 간 편집 충돌의 추가 검증이 필요하다.
- 회원·이메일·공식 서버 검증과 다른 7종은 구현 전이다. 준비 화면은 실제 순위나 회원 기능을 가장하지 않는다.
- 기록은 클라이언트 자료이므로 위변조 방지를 보장하지 않는다. 공식 참가 기록으로 전환할 수 없다.
