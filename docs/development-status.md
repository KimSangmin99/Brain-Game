# 개발 진행 기록

## 현재 상태 · 두 번째 구현 단위 (2026-11-05)

Vercel + Supabase PostgreSQL을 배포 구성으로 반영했다. 두 기억력 게임과 DB 연결 기반을 구현했으며 실제 서비스 연결은 프로젝트 식별 정보와 실행 환경의 인증 설정을 기다리고 있다. 아래 첫 구현 기록은 당시 상태를 보존한 것이다.

### 구현

- 시퀀스 기억의 6개 난이도 구간·30단계, 도형 제시·순서 입력·되돌리기·키보드·힌트·정답 비교·결과·다음 단계 개방을 추가했다.
- 패턴·시퀀스의 세션 저장·중단 복구·탭 잠금과 결과 계산을 공통화했다. 기존 pattern-v1 IndexedDB 기록을 유지하며 게임별 진행도와 기록을 분리했다. 홈의 이어하기는 최근 게임으로 연결된다.
- 서버 전용 PostgreSQL 연결과 트랜잭션 풀러 옵션, Drizzle 스키마·초기 SQL·별도 마이그레이션 명령을 추가했다. 9개 테이블에 RLS·비공개 스키마 권한을 설정했다.
- Vercel 빌드 설정과 서버 환경변수 예시, [연결·배포 안내](deployment.md)를 작성했다. 기술 설계의 상주 워커 계획을 예약 작업·DB lease 방식으로 변경했다.

### 검증

- TypeScript 검사와 프로덕션 빌드 통과. 프로덕션 서버에서 홈 HTTP 200, 시퀀스 초기화·저장, 최근 게임 이어하기 링크와 브라우저 실행 오류 없음을 확인했다.
- 게임·저장·DB 테스트 24개 통과. DB 검증은 로컬 PGlite에서 마이그레이션 재실행, ID 중복·이메일 상태·공식 중복 참가 제약, Data API 역할 접근 차단과 게임별 진행도를 확인했다.
- Chromium 브라우저 시나리오 9개 통과. 기존 패턴 시나리오 6개와 시퀀스 5문항 완료·기록 재접속·별도 단계 개방, 모바일 키보드·되돌리기·힌트·화면 넘침, 노출 중 새로고침 복구를 검증했다.
- 시퀀스 모바일 캡처를 확인했다. 실제 휴대폰과 시니어 사용자 플레이테스트는 아직 수행하지 않았다.
- 마이그레이션 CLI의 CommonJS 로딩 호환 문제를 수정했다. 자격 증명 없이 실행하면 DB에 접근하지 않고 필요한 환경변수를 안내한다.

### 남은 범위

1. 기존 Vercel·Supabase 프로젝트 확인, 안전한 자격 증명 설정, 원격 마이그레이션과 연결·TLS·권한 검증.
2. 나머지 6종 게임의 판정·예시 콘텐츠·학습 흐름 구현.
3. 회원·복구 이메일·기록 병합·클라우드 동기화, 공식 경쟁과 예약 작업 구현.
4. 8종 전체 콘텐츠 검수, 접근성·실기기·사용자 검증 및 운영 준비.

두 게임의 60단계는 파라미터와 생성 로직을 제공하는 상태다. 단계별 교육 콘텐츠 검수나 지능·인지 능력 향상 효과 검증이 완료된 것은 아니다. DB 테이블이 존재해도 계정·동기화 기능이 동작하는 것은 아니며, 현재 플레이 기록은 브라우저에만 저장된다. 실제 Supabase 적용·Vercel 배포·이번 코드의 GitHub 커밋과 푸시는 수행하지 않았다.

2026-11-05 · 첫 구현 단위

## 구현 범위

기획서 D01 중 프런트엔드 실행 기반과 버전 잠금, D02 패턴 복원용 플레이 상태, D03 게스트 플레이 흐름을 구현했다. D01의 PostgreSQL·마이그레이션은 아직 수행하지 않았다. 전체 개발 범위는 8종을 유지한다.

패턴 복원은 안내·조작 예제·제시·선택·판정·해설·결과·다음 단계로 이어진다. 힌트 사용과 중단 이력을 기록하고, 기존 완료를 보존한다. 단계별 6개 구간의 수치는 기획서와 일치하며 생성된 문제는 세션 안에서 중복되지 않는다.

## 구현상 제한

- 30개 단계의 수치·진행은 제공하지만 단계별 교육 목표에 맞춘 패턴 선정, 전체 대체 문제 풀, 사용자 난도 검증은 남아 있다.
- 자유 연습은 현재 열린 단계의 문제를 반복하는 기능이다. 쉬운 조건을 자동 추천하는 보충 연습과 복습 추천은 후속 구현이다.
- 전략 힌트 1단계를 제공한다. 현재 문제 힌트·풀이 열람은 아직 제공하지 않는다. 정답 제출 후 해설은 구현했다.
- 최근 미완료 시도를 이어가며, 노출 중 복구는 다른 문제로 대체하고 독립 성취에서 제외한다. IndexedDB를 사용할 수 없으면 저장 불가를 표시한다.
- Web Locks 지원 환경에서는 다른 탭의 동시 플레이를 막는다. 미지원 환경에서는 결과 중복·과거 상태 덮어쓰기 방지를 제공하지만 탭 간 편집 충돌의 추가 검증이 필요하다.
- 회원·이메일·공식 서버 검증과 다른 7종은 구현 전이다. 준비 화면은 실제 순위나 회원 기능을 가장하지 않는다.
- 기록은 클라이언트 자료이므로 위변조 방지를 보장하지 않는다. 공식 참가 기록으로 전환할 수 없다.

## 이번 검증 결과

- TypeScript 검사 통과.
- 프로덕션 빌드 통과. `npm start`로 기동한 서버에서 홈페이지 HTTP 200, 게임 화면 초기화·시작, 브라우저 실행 오류 없음을 확인했다.
- 게임 규칙·저장 단위 테스트 9개 통과.
- Chromium 브라우저 시나리오 6개 통과: 5문항 완료·기록 재접속·다음 단계 잠금, 노출 중 새로고침·새 문항 교체, 모바일 조작·힌트·가로 넘침, 분야 필터, 저장 실패 안내, 여러 탭 잠금·해제.
- PC 연구소 화면과 모바일 플레이 화면을 캡처해 확인했다. 실제 휴대폰·시니어 사용자 검증은 아직 수행하지 않았다.
- 초기화 중 Strict Mode의 중복 실행으로 탭 잠금이 충돌하는 문제를 수정하고 전체 브라우저 시나리오를 재실행했다.
