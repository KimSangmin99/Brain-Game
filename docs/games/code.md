# 코드 브레이커 · code-v1

2026-11-12. 네 번째 게임으로 구현한 추론 학습 게임이다. 위치·기호 일치 단서를 조합해 비밀 코드를 해독한다. A 디자인을 유지하며 코드 입력, 이전 추측 전체와 단서, 학습 도움을 함께 제공한다. 응답 시간 제한은 없다.

화면 예시: [PC](code-desktop.png) · [모바일 큰 글자·5자리](code-mobile.png). 로컬 테스트 예시이며 실제 회원 기록이 아니다.

## 진행과 입력

안내 → 예제 → 코드 하나 해독 → 결과·추측 회고 → 다음 단계 또는 새 코드 재도전. 각 구간의 첫 단계(1·6·11·16·21·26)는 예제에서 정확한 단서를 선택해야 시작할 수 있다. 예제의 정답 코드는 실제 도전에 사용하지 않는다.

칸을 선택하고 기호 버튼 또는 숫자 1~6으로 입력한다. 빈 다음 칸으로 이동하며, 좌우 방향키로 칸을 옮기고 Backspace/Delete로 지운다. 확정 전에는 수정할 수 있다. 빈칸·범위 밖 기호·중복 금지 단계의 중복·이미 제출한 조합은 시도 횟수에 넣지 않는다. 색에 더해 모양·이름으로 기호를 구분한다.

## 30단계

| 단계 | 자리 수 | 기호 수 | 중복 | 최대 추측 |
| --- | --- | --- | --- | --- |
| 1~5 | 3 | 4 | 없음 | 6 |
| 6~10 | 3 | 5 | 없음 | 6 |
| 11~15 | 4 | 5 | 없음 | 7 |
| 16~20 | 4 | 6 | 없음 | 8 |
| 21~25 | 4 | 6 | 허용 | 9 |
| 26~30 | 5 | 6 | 허용 | 10 |

각 단계에는 위치·포함·제외·모순 점검 등의 학습 목표를 표시한다. 코드는 구간 조건 안에서 무작위 생성한다. 재도전할 때 직전 코드와 다른 코드를 만든다. 생성 조건은 검증했으나 실제 사용자 난도와 학습 효과를 검증한 상태는 아니다.

## 판정과 점수

먼저 같은 자리의 같은 기호를 위치 일치로 센다. 해당 기호를 양쪽에서 제외한 뒤 남은 기호를 하나씩 대응해 기호 일치를 계산한다. 예를 들어 정답 A B A C, 추측 A A B D는 위치 1·기호 2다. 중복 기호는 정답에 남은 개수보다 많이 세지 않는다. 어느 칸이 일치하는지는 공개하지 않는다.

코드 전체가 일치하면 통과한다. 허용 횟수 M, 사용 추측 G에 대해 `8000 + floor(2000 × (M−G)/(M−1))`점이다. 첫 추측 10000점, 마지막 추측 8000점이며 시도 소진·건너뛰기·풀이 열람은 0점이다. 통과한 스테이지만 다음 단계를 열고 자유 연습은 개방에 반영하지 않는다.

이전 추측은 모두 남는다. 새 추측이 앞선 단서와 모순되면 제출 후 이유를 안내한다. 실패·성공 결과에서 정답 코드와 전체 추측을 함께 비교한다.

## 도움과 중단

1단계 도움은 전략 설명이다. 2단계는 이전에 공개된 단서만으로 가능한 조합 수와 최대 3개의 예시를 계산한다. 실제 비밀 코드를 조회해 후보를 선정하지 않는다. 남은 후보가 하나면 그 조합도 보일 수 있으며 도움 사용으로 기록한다. 정답 직접 열람은 별도 안내를 펼쳐 ‘풀이 확인하고 종료’를 누르면 0점으로 끝낸다.

새로고침·탭 숨김·나가기는 같은 코드, 추측 이력, 작성 중 조합, 도움 상태를 보존하고 일시정지한다. 이어갈 때 코드를 교체하지 않으며 중단 이력을 남긴다. 힌트·중단·풀이 열람이 있는 시도는 독립 해결로 표시하지 않는다.

## 기록과 계정

기존 IndexedDB와 계정별 저장 공간에 code-v1을 추가한다. 기존 세 게임 기록의 형식과 진행을 유지한다. 한 코드 결과는 answers 1개와 추측 이력으로 저장하며 5문항 기록과 구분한다. 서버는 코드 조건·전체 피드백·종료 이유·완료 형식을 검증한 후 점수와 진행을 다시 계산한다. 개인 imported/unverified 기록이며 공식 경쟁에 사용하지 않는다.

완료 기록의 계정 저장·게스트 가져오기·다른 기기 조회는 기존 API를 사용한다. 진행 중인 코드는 현재 기기에만 저장된다. 별도 DB 마이그레이션은 없다. 계정 업데이트 SQL(0001)이 적용된 기존 Vercel·Supabase 설정을 그대로 사용한다.

## 검증 범위

단위 테스트는 중복 판정, 모든 30단계 조건, 729개 작은 조합 쌍의 독립 다중집합 계산 비교, 공개 단서 후보 필터, 입문 모든 정답의 단서 기반 해독, 점수 경계·실패·도움·중단·부정한 기록·기존 저장 호환을 검사한다. 브라우저에서는 플레이·기록·분리된 진행·키보드·모바일·복구·회원 저장과 새 브라우저 복원을 확인한다. 계정 DB 검증은 실제 HTTP 처리 함수와 로컬 PGlite를 연결한 검사이며 운영 Supabase 검증을 대체하지 않는다.

프로덕션 화면 감사: `node scripts/audit-code.mjs` (기본 localhost:3100, CODE_BASE_URL로 변경). 로컬 호스트만 허용하며 테스트용 완료 기록으로 대표 단계를 연다. 캡처와 결과는 test-results/code-production에 남기고 운영 서버로 전송하지 않는다.
