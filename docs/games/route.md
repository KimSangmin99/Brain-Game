# 경로 설계 · route-v1

2026-11-12. 여섯 번째 게임이자 두 번째 논리 게임이다. 출발에서 도착까지 상하좌우로 길을 잇고 필수 지점·방문 순서·이동 상한을 함께 만족시킨다. 일반 스테이지와 자유 연습을 제공하며 응답 시간 제한은 없다.

화면 예시: [PC](route-desktop.png) · [360px 큰 글자·6×6](route-mobile.png). 실제 회원 자료가 아닌 로컬 테스트 기록이다.

## 진행과 조작

안내 → 조작 예제 → 경로 퍼즐 하나 → 조건 확인 → 결과·예시 경로로 이어진다. 구간 첫 단계(1·6·11·16·21·26)는 예제를 직접 완료해야 한다. 예제와 실제 도전의 지도는 다르며 예제의 오류와 길 안내는 본 도전의 도움 상태에 반영하지 않는다.

현재 끝 칸에 상하좌우로 붙은 칸을 눌러 이동한다. 지도에서 방향키, 별도 방향 버튼도 사용할 수 있다. 방문한 칸을 누르면 해당 칸까지 경로를 잘라 되돌린다. Backspace/Delete와 ‘한 칸 되돌리기’, ‘처음부터 다시’도 제공한다. 되돌리기는 재방문 경로를 추가하지 않고 초안을 수정하는 동작이며 편집 횟수에 점수 불이익이 없다.

지도는 출발 ‘출’·도착 ‘도’·장애물 ‘×’·필수 지점 A/B/C를 표시한다. 작성한 경로는 색·순번·화살표를 함께 표시하고 칸의 접근성 이름에 행·열·역할·경로 순번을 넣는다. Tab은 현재 끝 칸으로 진입하고 방향키는 경로를 한 칸씩 입력한다. 360px 큰 글자에서 6×6 칸의 최소 조작 영역은 44px다.

장애물·대각선·떨어진 칸·지도 밖 입력은 초안과 확인 횟수를 바꾸지 않는다. 도착지 이후에는 계속 진행하지 않고 확정하거나 되돌린다. 최종 조건은 ‘경로 확정’ 후 검사한다. 화면의 이동 수는 경로 칸 수−1이며 출발 칸은 0회다.

## 30단계

| 단계 | 격자 | 필수 지점 | 방문 순서 | 이동 상한 |
| --- | --- | --- | --- | --- |
| 1~5 | 4×4 | 0곳 | 없음 | 없음 |
| 6~10 | 4×4 | 1곳 | 없음 | 없음 |
| 11~15 | 5×5 | 1곳 | 없음 | 없음 |
| 16~20 | 5×5 | 2곳 | 자유 | 없음 |
| 21~25 | 6×6 | 2곳 | A → B | 없음 |
| 26~30 | 6×6 | 3곳 | A → B → C | 지도별 표시 |

각 단계는 새 규칙 도입·적용·혼동 구분·변형·종합 목표를 가진다. B6의 상한은 최단 이동 수 또는 그보다 2·4회 여유를 둔 수치이며 지도에 들어가기 전과 플레이 중에 정확한 값을 표시한다.

## 지도 검수와 탐색

- `scripts/generate-route-bank.py`가 고정 시드로 단계당 5개, 총 150개 지도를 생성한다. 모든 도착 경로를 셀 재방문 없이 열거해 조건 충족과 최단 이동 수를 검증하고 `src/lib/route-bank.json`에 저장한다. 실행 시 임의 지도를 즉석 출제하지 않는다.
- 각 단계의 첫 지도는 예제이고 실제 도전은 나머지 4개에서 선택한다. 재도전은 직전 지도도 제외한다. 모든 지도 ID는 전체 은행에서 서로 다르며 지도·필수 조건·상한을 포함한다.
- B1은 서로 다른 길이의 유효 경로가 있다. B2~3은 지점을 생략한 최단 길이보다 필수 지점을 지나는 최단 길이가 길다. B4는 두 지점을 서로 다른 순서로 방문하는 유효 경로가 모두 있다. B5~6은 지점은 모두 지났지만 순서가 다른 경로가 존재하고, B6은 순서를 지켰어도 상한을 초과하는 경로가 존재한다.
- 앱의 최단 경로 탐색은 방문한 셀 집합을 유지하는 완전 탐색과 거리 하한으로 계산한다. `(현재 칸, 방문 지점)`만 저장하는 BFS는 같은 칸을 다시 지나는 잘못된 해를 만들 수 있어 사용하지 않는다. 독립적인 테스트는 방문 셀을 보존하는 별도의 너비 우선 열거와 비교한다.
- 현재 지도는 작고 검증된 유한 은행이다. 생성 과정의 최대 탐색 규모는 지도당 4010노드다. 사용자 정의 지도를 받아 검색하는 기능은 없다. 서버는 은행의 실제 지도·조건·최단 이동 수와 일치하는지 확인한 뒤 기록을 검증한다.
- `route-v1` / `route-content-v1`로 판정과 콘텐츠를 버전 관리한다. 공개한 콘텐츠를 수정할 때는 새 버전으로 분리해야 한다. 생성 스크립트는 재현·검수 도구이며 공개 버전의 자동 갱신 명령이 아니다.

## 판정·점수·도움

유효한 연결, 출발·도착, 필수 지점, 방문 순서, 이동 상한을 모두 만족하는 경로는 모양이 달라도 정답이다. 최단 경로와 같은 배열인지 비교하지 않는다. 실패는 0점이며, 성공은 `8000 + floor(2000 × L / S)`점이다. L은 조건을 만족하는 최단 이동 수, S는 제출 경로의 이동 수다. 최단 해결은 10000점, 더 긴 유효 경로도 통과한다.

틀린 확정은 경로를 고정하고 조건별 설명을 보여 준 뒤 같은 초안을 수정할 수 있게 한다. 구체적 피드백 후 해결은 도움 사용으로 기록한다. 실제 제출 전 중복 클릭·이동·되돌리기를 오답이나 도움으로 세지 않는다. 수정 후 점수도 최종 경로의 L/S로 계산한다.

1단계 힌트는 지점과 도착을 구간으로 나누는 전략이다. 2단계는 현재 초안을 유지하면서 이어갈 수 있는 한 가지 다음 칸을 좌표·테두리로 표시한다. 유효한 연장이 없으면 이전 칸으로 되돌리도록 안내한다. 이 과정은 도움 사용으로 기록하고 정답 전체 경로는 표시하지 않는다. 예제에는 별도의 전체 좌표 안내가 있다.

풀이 열람은 별도 안내를 펼쳐 종료 버튼을 눌러야 하며 0점으로 끝난다. 건너뛰기도 0점이다. 자유 연습은 단계 개방에 반영하지 않는다. 힌트·풀이·중단·오류 피드백이 있는 도전은 독립 해결과 구분한다.

결과는 점수·제출 이동 수·최단 이동 수를 보여 주며 ‘내 제출 경로’와 ‘최단 예시 경로’를 전환해 조건별 설명을 확인한다. 다른 유효한 경로도 인정함을 함께 설명한다.

## 저장과 계정

새로고침·탭 숨김·나가기는 같은 지도·작성 중 경로·마지막 제출·확인 횟수·피드백·도움 상태를 보존하고 중단 이력을 남긴다. 피드백 화면에서 멈췄다면 그 화면으로 복구한다.

기존 IndexedDB 버전과 계정별 저장 공간에 route-v1을 추가한다. 한 퍼즐 결과는 answers 1개와 마지막 제출로 저장하고 기존 다섯 게임의 자료를 보존한다. 완료 결과는 기존 회원 API로 동기화하고 진행 중 경로는 현재 기기에만 남는다. 서버는 지도의 은행 일치, 연결·최종 조건·종료·도움 상태를 검증하고 점수와 게임별 진행을 계산한다. 개인 imported/unverified 기록으로, 공식 경쟁에 사용하지 않는다.

추가 SQL·환경변수는 없다. 기존 계정 업데이트 SQL(0001)이 적용된 Vercel·Supabase 구성을 사용한다. 로컬 HTTP/PGlite 검증은 실제 운영 DB·TLS·풀러 검증을 대체하지 않는다.

## 검증과 남은 작업

단위 검증은 150개 지도 전체의 모든 도착 경로와 최단 거리를 독립적으로 비교한다. 짧지만 지점 누락·순서 오류·상한 초과, 재방문으로만 가능한 잘못된 해, 다른 유효 경로, 긴 경로의 점수, 수정·복구·부정한 기록·기존 저장 호환을 검사한다. 브라우저는 공개된 지도만으로 실제 조작·기록·분리된 단계·키보드·되돌리기·힌트·모바일·계정 저장과 다른 브라우저 조회를 확인한다.

프로덕션 화면 감사는 `node scripts/audit-route.mjs`로 실행한다. 기본 localhost:3100이며 ROUTE_BASE_URL로 바꿀 수 있으나 로컬 호스트만 허용한다. 실제 게스트 플레이로 30단계를 모두 해결하고 그 로컬 기록으로 360·768px 대표 단계와 큰 글자를 확인한다. test-results/route-production에 결과와 캡처를 남긴다. 이번 검증은 PC 30단계 해결·저장과 입력 화면 45개 상태를 통과했다.

공식 경쟁, 장기 반복 노출 표시·복습 추천·쉬운 조건의 자동 보충 연습, 실제 시니어 사용자·실기기 난도와 교육 효과 검증은 후속 작업이다.
