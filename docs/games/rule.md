# 규칙 분석 · rule-v1

2026-11-09. 세 번째 게임으로 구현한 추론 학습 게임이다. A 디자인을 유지하며 도형 배열의 방향·개수·표식을 비교해 다음 항목을 고른다. 일반 스테이지와 자유 연습을 제공한다. 공식 경쟁은 포함하지 않는다.

화면 예시: [PC](rule-desktop.png) · [모바일](rule-mobile.png). 로컬 테스트용 예시이며 실제 회원 기록이 아니다.

## 이용 흐름

안내 → 예제(구간의 첫 단계에서는 필수) → 본문항 5개 → 문항별 판정·해설 → 결과·문항 회고 → 다음 단계/연습. 응답 시간 제한은 없다. 한 선택지를 고른 뒤 확정 전까지 바꿀 수 있다. 미선택 확정은 막고, 건너뛴 문항은 0점이다. 4개 정답부터 통과하며 점수는 정답 수×2000이다.

1~4 숫자 키와 방향키로 선택할 수 있다. 텍스트 입력·설정 입력 중에는 게임 단축키를 처리하지 않는다. 표식은 색과 함께 원·삼각형·사각형·마름모, 방향 이름과 개수로 제공한다. 정답·선택·오답은 체크·텍스트를 함께 표시한다.

PC에서는 선택지 4개를 한 줄에 배치하고 단서를 비교하며 스크롤할 수 있도록 문제 항목을 고정한다. 교대 문제의 6개 단서와 빈칸도 한 줄로 읽는다. 모바일은 2열로 번호 순서에 따라 읽고, 큰 글자에서는 선택지를 1열로 늘린다. 단서는 응답 중 사라지지 않는다.

## 30단계

| 단계 | 규칙 범위 | 관찰 항목 |
| --- | --- | --- |
| 1~5 | 단일 속성 순환 | 방향 90도 회전 또는 표식의 정·역순 순환 |
| 6~10 | 단일 속성 증감 | 개수가 1개씩 증가·감소, 1~7개 범위. 7단계는 증가, 8단계는 감소 목표와 맞춤 |
| 11~15 | 두 속성 독립 변화 | 방향+표식 또는 방향+개수 |
| 16~20 | 교대 부분열 | 1·3·5번째와 2·4·6번째를 따로 비교해 7번째 예측 |
| 21~25 | 독립+교대 | 홀수·짝수 줄의 서로 반대 방향 회전과 표식 순환 결합 |
| 26~30 | 앞서 배운 규칙 혼합 | 위 8개 세부 유형에서 문제별 범위를 안내 |

각 단계는 구간 목표와 5개의 교육 역할에 맞는 목표 문구를 가진다. 1·6·11·16·21·26단계는 예제의 설명과 같은 답을 선택한 뒤 본문항으로 들어간다. 예제는 5문항 생성에서 제외하고 점수·힌트 성취에 넣지 않는다.

## 문제 생성과 유일성

- 임의 수열을 무제한 추측하게 하지 않고 문제마다 허용 규칙군을 명시한다.
- 방향·표식은 4항 순환, 개수는 ±1, 교대는 각 부분열을 따로 적용하는 유한 규칙 카탈로그다.
- 같은 유형·같은 단서 전체에 맞는 모델들의 다음 항목이 일치하는 경우에만 문제 은행에 남긴다. 일치하지 않으면 제외한다.
- 선택지는 중복 없이 4개이고 예측 항목과 일치하는 것은 정확히 1개다. 두 속성 문제의 오답은 첫 조건만 오류 / 두 번째만 오류 / 둘 다 오류로 구성해 한 속성만 보아 답을 고를 수 없도록 한다.
- 세션 안에서 단서 묶음이 중복되지 않는다. 새 세션에서는 유한 은행의 같은 문제가 다시 나올 수 있다. 장기 노출 이력을 이용한 재출제 제어는 후속 범위다.
- `rule-v1`과 `rule-content-v1`로 판정·콘텐츠 버전을 기록한다. 공개된 버전의 규칙이나 해설을 변경할 때는 새 버전을 추가하고 이전 기록의 판정 지원을 유지해야 한다.

정답 유일성은 안내한 유한 규칙군 안에서의 보장이다. 모든 수학적·임의 규칙의 유일성을 주장하지 않는다. 학습 난이도·해설 이해도는 실제 사용자 테스트로 추가 조정한다.

## 힌트와 해설

1단계는 속성을 따로 보거나 홀수/짝수를 나누는 전략을 제안한다. 2단계는 비교할 위치를 구체화하고 교대 문제의 홀수 위치를 표식과 텍스트로 강조한다. 힌트는 답을 대신 선택하지 않는다. 도움 상태는 남으며 힌트를 써도 단계 완료는 유지한다.

확정 후 정답 항목, 선택 항목이 놓친 속성, 각 단서와 규칙의 관계를 설명한다. 교대 문제도 홀수·짝수 양쪽 단서를 모두 해설에 포함한다. 결과에서는 5문항의 해설을 다시 펼쳐 볼 수 있다.

## 저장과 복구

기존 IndexedDB 데이터베이스와 계정별 저장 공간을 유지하며 rule-v1을 추가한 합집합 스키마로 읽는다. 기존 pattern-v1·sequence-v1을 변환·삭제하지 않는다. 규칙 분석의 단계 진행과 탭 잠금은 다른 게임과 독립이다.

새로고침·탭 숨김·나가기로 답안 작성이 중단되면 미확정 선택을 지우고 중단 상태로 저장한다. 이어갈 때 현재 미완료 문제만 새 단서로 교체하고 이전에 확정한 문항·도움·중단 이력은 보존한다. 독립 해결 판정에서 중단을 구분한다.

완료 결과는 기존 회원 기록 API로 저장·가져오기·기기 간 조회한다. 서버는 버전·문제·단계 범위·선택·정오·도움 상태를 다시 검증하고 개인 기록으로만 저장한다. imported/unverified이며 공식 순위로 전환하지 않는다. 기존 attempts·progress 스키마가 rule 게임을 이미 허용하므로 추가 DB 마이그레이션은 필요 없다. 사용자가 계정 업데이트 SQL 완료를 확인했으나 이 작업에서 원격 DB를 직접 검증한 것은 아니다.

## 확인한 범위와 남은 작업

30단계의 유효 생성 규칙·예제·5문항·두 단계 힌트·해설·진행·저장·복구·계정 동기화를 구현했다. 수치·콘텐츠 생성의 정적 검증과 브라우저 흐름을 확인했으며, 실제 시니어 사용자·실기기 난이도 검증과 교육 효과 검증은 남아 있다. 나머지 룰 스위치, 공식 경쟁, 복구 이메일·탈퇴는 별도 후속 범위다.


프로덕션 화면 감사: `node scripts/audit-rule.mjs` (기본 localhost:3100, RULE_BASE_URL로 변경). 29개 완료 단계의 로컬 전용 예시를 넣어 대표 8개 단계와 큰 글자를 확인하고 test-results/rule-production에 캡처한다. 실제 운영 기록을 만들거나 외부로 전송하지 않는다.
