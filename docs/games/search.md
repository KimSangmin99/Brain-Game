# 신호 탐색 · search-v1

2026-11-12. 일곱 번째 게임이자 첫 주의·판단 게임이다. 제시한 모양·표식 조건을 유지하며 모든 목표를 찾아 선택하고 확정한다. 일반 스테이지와 자유 연습은 시간 제한이 없으며 공식 30초 경쟁은 포함하지 않는다.

화면 예시: [PC](search-desktop.png) · [360px 큰 글자·5×5](search-mobile.png). 실제 회원 자료가 아닌 로컬 테스트 기록이다.

## 진행과 조작

안내 → 예제 → 탐색판 3개 → 보드별 피드백 → 결과·회고로 이어진다. 구간 첫 단계(1·6·11·16·21·26)는 예제의 목표를 빠짐·오선택 없이 선택해야 시작할 수 있다. 예제 오류는 실제 도전의 점수나 도움 상태에 반영하지 않는다. 본문항은 예제와 다른 탐색판이다.

목표 조건은 보드 위에 텍스트와 그림으로 계속 표시한다. 칸을 누르거나 Enter/Space로 선택하고 다시 누르면 취소한다. 전체 선택 해제도 제공한다. 방향키는 선택을 바꾸지 않고 포커스만 이동한다. Tab으로 탐색판의 현재 포커스 칸에 진입한다. 모양·표식·행·열·선택 상태를 접근성 이름으로 제공한다.

일반 모드는 충분히 살펴보고 확정할 수 있다. 선택한 개수만 표시하며 실제 목표 개수는 확정 후 피드백에서 공개한다. 선택 수를 목표 수에 맞춰 제한하지 않고 0개 선택도 확정할 수 있다. 선택 테두리와 체크는 선택 상태이며 정답 표시가 아니다. 보드 확정 후에는 원 선택을 고치지 않고 새 보드에서 다시 연습한다.

## 30단계와 시각 조건

| 단계 | 격자 | 목표 수 | 조건 |
| --- | --- | --- | --- |
| 1~5 | 3×3 | 2개 | 모양 하나 |
| 6~10 | 3×3 | 3개 | 표식 하나, 모양 무관 |
| 11~15 | 4×4 | 3개 | 모양과 표식 모두 |
| 16~20 | 4×4 | 4개 | 두 조건 + 비슷한 표식의 방해 대상 증가 |
| 21~25 | 5×5 | 5개 | 넓어진 판에서 두 조건 유지 |
| 26~30 | 5×5 | 6개 | 목표와 부분 일치 방해 대상 탐색 |

모양은 원·삼각형·사각형·마름모다. 표식은 점 하나·점 두 개·가로줄 하나·가로줄 두 개다. 점 계열과 줄 계열에 색을 중복 표시하되 하나/둘은 같은 색이므로 색만으로 구분할 수 없다. 모양이 무관한 목표는 모양을 특정하는 실선 대신 중립 점선 틀을 사용하고, 무관한 속성을 문장으로 명시한다.

두 조건 보드는 모양만 맞는 대상과 표식만 맞는 대상을 반드시 포함한다. 11~15단계는 다른 표식 계열의 부분 일치 방해 대상을 제공한다. 16단계부터 같은 모양·같은 색 계열에서 점/줄의 하나와 둘만 다른 방해 대상을 늘린다. 한 조건만 보고 선택하면 오선택이 생긴다. 비슷하다는 것은 이 구성 규칙을 뜻하며 실제 사용자의 지각 난도 검증은 별도다.

## 생성·검증

문제는 `search-content-v1`의 생성 규칙으로 만든다. 격자 크기·목표 수·조건 종류·부분 일치 방해 대상 수를 검증한다. 문제 ID는 목표 조건과 모든 칸의 모양·표식을 포함하며 저장 자료와 다시 대조한다. 같은 시도의 본 보드 3개와 예제는 중복되지 않는다.

예제는 단계별 고정 난수로 재현하며 변경되지 않는 복사본을 반환한다. 보드의 목표를 판정하는 규칙은 생성 코드와 분리돼 있다. 서버는 목표 조건·대상 분포·ID·선택 범위를 검증하고 선택 결과와 점수를 다시 계산한다. 플레이 시 실제 선택을 했는지 증명하는 서버 권한형 출제는 아니며 개인 imported/unverified 기록이다.

무작위 생성은 유효한 조건의 조합 공간을 사용한다. 현재 시도의 확정한 보드와 이어가기 직전 중단 보드는 교체 출제에서 제외한다. 장기 노출 추적·반복 표시·자동 복습 추천은 후속 범위다.

## 점수와 통과

보드별로 맞게 선택 TP, 오선택 FP, 놓침 FN을 구분한다. 실제 목표 수 T>0을 보장하며 점수는 `floor(10000 × max(0, TP−FP) / T)`다. 예를 들어 목표 3개 중 정답 2개와 다른 대상 1개를 선택하면 TP=2·FP=1·FN=1, 3333점이다. 모든 목표와 모든 방해 대상을 선택하면 현재 모든 단계에서 0점이다.

세 보드 점수의 평균을 내고 소수점을 버린다. 8000점 이상이면 통과하며 모두 완벽해야 하는 것은 아니다. 예를 들어 10000·10000·4000은 8000점으로 통과한다. ‘완벽 보드’는 놓침·오선택이 모두 없는 보드 수이며 통과 점수와 구분한다. 초기 난도·통과 기준은 사용자 검증 전 설계값이다.

건너뛰기·풀이 열람은 해당 보드를 0점·모든 목표 미응답으로 확정하고 다음 보드를 계속할 수 있다. 기존 선택은 점수 집계에서 제외한다. 한 보드라도 0점이면 남은 두 보드가 만점이어도 평균 6666점이므로 이번 시도는 통과하지 못한다. 풀이 열람은 별도 안내를 펼쳐 버튼을 눌러 확정한다.

오답 보드를 보고 같은 보드를 수정해 점수를 올리는 흐름은 없다. 일반 오선택은 점수에 반영하며 자동으로 도움 사용으로 표시하지 않는다. 힌트·풀이 열람·탐색 중 중단은 독립 통과와 구분한다. 자유 연습은 단계 개방에 반영하지 않는다.

## 피드백·도움·복구

확정 전에는 맞음/틀림/놓침을 표시하지 않는다. 확정 후 목표와 선택을 비교해 ‘정답’·‘놓침’·‘오선택’을 색·테두리·텍스트로 구분한다. 표식과 판정 이름이 겹치지 않도록 피드백 칸 높이를 늘린다. 목표 수와 TP·FP·FN, 점수, 해당 위치가 어떤 조건과 맞거나 다른지를 제공한다. 결과에서는 세 보드를 다시 선택해 회고한다.

1단계 힌트는 위에서 아래로 한 줄씩 살펴보고 모양·표식을 따로 확인하는 전략이다. 2단계는 목표가 포함된 한 행을 강조한다. 행 전체가 정답이라는 뜻이 아니며 개별 정답 위치를 자동 선택하지 않는다. 두 단계 모두 도움 사용으로 기록한다.

탐색 중 새로고침·탭 숨김·나가기는 현재 선택을 지우고 중단으로 저장한다. 이어갈 때 미확정 보드만 다른 목표·배치로 교체한다. 앞서 확정한 보드·점수·도움 이력은 유지하며 새 보드의 구간 힌트는 초기화한다. 이미 확정한 피드백 화면에서 새로고침하면 같은 보드와 피드백을 보존한다.

## 저장과 계정

`search-v1`은 보드 3개, 각각의 선택·점수·집계·건너뛰기/풀이·힌트와 세션 도움/중단을 저장한다. 기존 IndexedDB 버전과 회원별 저장 공간을 유지하고 기존 여섯 게임의 기록을 보존한다. 계정 완료 API는 신호 탐색의 answers 3개를 별도로 검증하고 평균 점수와 게임별 진행을 계산한다. 완료 결과만 동기화하며 진행 중 탐색판은 현재 기기에 남는다.

추가 SQL·환경변수는 없다. 기존 계정 업데이트 SQL(0001)이 적용된 Vercel·Supabase 구성을 사용한다. HTTP 처리 함수와 로컬 PGlite 검증은 운영 DB·TLS·풀러 검증을 대체하지 않는다.

## 검증 도구와 남은 작업

단위 검증은 30단계의 서로 다른 600개 생성 보드를 독립적으로 분류하고, 작은 보드의 가능한 선택 조합 512개를 대조한다. 부분 일치 방해의 필요성·단계별 목표 수·점수 경계·무차별 선택·예제 분리·불변 결과·복구·부정한 기록·기존 저장 호환을 검사한다. 브라우저는 공개 목표와 실제 표시된 모양·표식만으로 실제 플레이·키보드·모바일·피드백·중단 교체·회원 저장·다른 브라우저 조회를 확인한다.

프로덕션 감사는 `node scripts/audit-search.mjs`로 실행한다. 기본 localhost:3100이며 SEARCH_BASE_URL로 바꿀 수 있으나 로컬 호스트만 허용한다. 30단계의 90개 보드를 실제 게스트 조작으로 완료하고, 로컬 완료 기록을 이용해 대표 단계의 360·768px와 큰 글자 화면을 확인한다. test-results/search-production에 결과와 캡처를 남긴다. 이번 감사는 PC 30단계의 90개 보드와 추가 반응형 보드 14개의 만점·피드백, 입력 화면 45개 상태를 통과했다.

공식 30초 경쟁·입력 방식별 순위, 장기 노출 추적·복습 추천·쉬운 조건의 자동 보충 연습, 실제 시니어 사용자·실기기·교육 효과 검증은 후속 작업이다.
