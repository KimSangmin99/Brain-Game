# 룰 스위치 · switch-v1

2026-11-13. 여덟 번째 게임으로 모양·밝기·방향 중 현재 지시한 속성에 맞춰 두 버튼 중 하나를 누른다. 기억·추론·논리·주의 분야에 각각 두 게임을 제공하는 기본 플레이 구현을 마쳤다. 운영 출시·교육 효과 검증의 완료를 뜻하지 않는다.

화면 예시: [PC](switch-desktop.png) · [360px 큰 글자](switch-mobile.png). 개인 정보가 없는 로컬 테스트 화면이다.

## 진행과 응답

안내 → 예제 → 지시 안내 1초 → 준비 → 문항 시작 → 자극·응답 → 피드백 → 다음 문항 → 빈 간격 0.5초로 진행한다. 규칙이 바뀌면 빈 간격 뒤 지시를 1초 더 안내하고 준비로 이동한다. 구간 첫 단계(1·6·11·16·21·26)는 직접 정답을 고른 예제를 완료해야 한다. 예제 실수는 실제 도전의 도움으로 기록하지 않는다.

준비 화면은 시간 제한이 없다. 현재 지시·응답 뜻과 도움을 읽은 뒤 ‘문항 시작’을 누른 순간부터 자극을 제시하고 스테이지의 응답 시간을 측정한다. 안내·빈 간격·준비·피드백은 응답 시간에서 제외한다. 20문항은 사용자가 준비와 다음 버튼으로 진행하는 학습형 흐름이다. 자극이 자동으로 이어지는 연속 반응 검사와 구분한다.

1·2 키 또는 두 응답 버튼으로 입력하며 첫 유효 응답이 바로 확정된다. 자극 전 입력·키 반복·이미 확정한 문항의 두 번째 응답·이전 문항 ID의 입력을 거부한다. 준비 버튼은 자극 제시 뒤 같은 위치에 비활성 상태로 남아 연속 클릭이 응답 버튼으로 이어지지 않는다.

| 현재 지시 | 1번 | 2번 |
| --- | --- | --- |
| 모양 | 원 | 삼각형 |
| 밝기 | 밝은 표식 | 어두운 표식 |
| 방향 | 위 | 아래 |

현재 규칙과 버튼 뜻을 과제 위에 보여 준다. 안내·준비·자극 단계에서는 과제 영역으로 화면 위치를 맞추고 작은 화면의 버튼 행을 압축해 지시와 응답을 함께 보도록 한다. 자극에 표시한 속성 이름·접근성 이름·모양·화살표·어두운 표식의 두 줄로 구분을 보조한다. 사용하지 않는 속성은 초기 구간에서 중립 처리한다. 표시 속성 텍스트로도 판단할 수 있는 학습용 게임이며 순수 시지각 검사로 해석하지 않는다.

## 30단계 조건

| 단계 | 지시 | 전환 간격 | 응답 시간 | 자극 속성 |
| --- | --- | --- | --- | --- |
| 1~5 | 모양 | 없음 | 5초 | 모양만 |
| 6~10 | 밝기 | 없음 | 4초 | 모양·밝기 |
| 11~15 | 모양·밝기 | 5문항 | 5초 | 모양·밝기 |
| 16~20 | 모양·방향 | 4문항 | 4초 | 모양·방향 |
| 21~25 | 밝기·방향 | 3문항 | 4초 | 밝기·방향 |
| 26~30 | 모양·밝기·방향 | 2문항 | 4초 | 세 속성 |

각 시도는 20개의 서로 다른 문항 ID를 갖는다. 두 응답이 각각 10개이고 규칙별 응답 수 차이는 최대 1개다. 동일 응답이 4회 연속되거나 완전 교대만 되는 묶음은 제외한다. 여러 속성을 표시하는 구간은 현재 속성과 다른 속성의 응답이 충돌하는 자극을 최소 6개, 각 현재 규칙에 최소 하나 포함한다. 이는 생성 조건이며 실제 난도는 사용자 검증 전 설계값이다.

자극 그림은 반복될 수 있다. 첫 구간의 가능한 모양은 두 가지이며 UUID만 달라졌다고 새로운 시각 자극으로 세지 않는다. 장기 노출 추적·적응형 난도·자동 보충 추천은 후속 범위다.

## 시간·점수·피드백

`performance.timeOrigin + performance.now()` 기반의 단조 시계로 현재 페이지의 시간 차를 측정한다. 타이머 콜백이 늦게 실행되더라도 입력 시각이 마감 시각 이상이면 선택을 반영하지 않고 시간 초과로 확정한다. 마감 1ms 전까지의 입력은 인정하고 정확히 마감 시각의 입력은 시간 초과다. 카운트다운만 100ms마다 화면에 갱신하며 저장 자료는 상태 전이 때 갱신한다. 이는 브라우저 측정이며 공식 시간 증명이 아니다.

정답마다 500점, 20문항 중 16개 정답(8000점)부터 통과한다. 선택 오답·시간 초과·건너뜀·풀이 열람을 별도로 저장하고 모두 해당 문항 0점이다. 시간 초과는 선택값 없이 제한 시간 길이로 저장한다. 풀이 열람은 별도 안내에서 확정하며 도움 사용을 기록한다.

확정 후 실제 지시·자극 속성·내 응답·맞는 판단 기준을 설명한다. 결과에는 규칙별 정확도, 규칙 변경 직후의 정확도(첫 문항 제외), 선택 오답·시간 초과·건너뜀·풀이 열람 수, 정답 응답의 대략적 평균 시간을 제공한다. 20문항을 펼쳐 다시 살펴볼 수 있다. 지능·인지 능력 진단이나 향상 보장의 근거로 표시하지 않는다.

전략 힌트와 응답 기준 힌트는 도움 사용으로 저장한다. 시간 제한이 있는 자극 제시 중에는 힌트를 열 수 없고 준비에서 읽는다. 자유 연습은 항상 시간 제한 없이 `timing=untimed`로 저장하고 자극 중에도 도움을 받을 수 있다. 연습 점수는 스테이지 개방에 반영하지 않는다. 도움·풀이·자극 노출 중 중단은 독립 통과와 구분한다.

## 중단·저장·검증

새로고침·탭 숨김·나가기로 자극 노출을 중단하면 아직 확정하지 않은 현재 문항만 다른 실제 속성 조합으로 바꾼다. 같은 규칙·구간 조건을 유지하고 이미 확정한 응답과 도움은 보존한다. 교체 후 전체 응답 10:10 조건은 달라질 수 있으며 중단 이력으로 구분한다. 준비·빈 간격·지시 안내에서 멈췄다면 자극을 보지 않았으므로 같은 문항을 준비부터 이어가고 그 멈춤만으로 중단 이력을 추가하지 않는다. 재개할 때 규칙을 1초 다시 안내한다. 피드백·결과는 같은 자료로 복구한다.

`switch-v1` / `switch-content-v1`로 20문항·응답 이유·선택·응답 시간·힌트·모드/시간 조건·중단·revision을 저장한다. 단계에 맞는 속성·규칙 순서·문항 ID·정오·시간 경계·도움·완료 순서를 Zod로 재검증한다. 기존 IndexedDB와 일곱 게임의 기록을 유지하고 계정 API는 answers 20개와 500점 단위 점수를 계산한다. 서버가 출제·응답 시점을 증명하는 구조는 아니며 개인 imported/unverified 기록이다. 진행 중 시도는 현재 기기에, 완료 기록만 계정에 동기화한다.

추가 SQL·환경변수는 없다. 기존 계정 SQL(0001)이 적용된 Vercel·Supabase 구성을 사용한다. 운영 배포는 Vercel에서 별도로 확인해야 한다.

검증 명령: `npm run typecheck`, `npm test`, `npm run test:e2e -- --workers=2`, `npm run build`. 프로덕션 서버를 실행한 뒤 `node scripts/audit-switch.mjs`로 30단계·600응답과 대표 반응형 화면을 검사한다. 전수 조작 검사는 Playwright 시계로 간격·안내를 진행하며 네이티브 타이머의 시간 초과는 별도 E2E에서 확인한다. PGlite 계정 검사는 운영 Supabase·TLS·풀러·실기기·실제 사용자·교육 효과 검증을 대체하지 않는다.
