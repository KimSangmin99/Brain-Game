# 개발 작업과 검증 기준

상태: v0.2. 일정 대신 완료 조건으로 진행한다. 이 목록은 개발 계획이며 코드 작성 승인이나 작업 완료 보고가 아니다.

## 1. 구현 순서

| 단계 | 작업·산출물 | 선행 | 완료 기준 |
| --- | --- | --- | --- |
| D01 기반 | 버전 고정, 실행 문서, DB 마이그레이션, 오류·로그 규칙 | 문서 기준안 | 깨끗한 환경에서 설치·기동·DB 준비 재현 |
| D02 공통 플레이 | 상태 전이, 입력, 타이머, 결과·힌트, 콘텐츠 버전 | D01 | 하나의 세션을 시작·중단·복원·완료 가능 |
| D03 패턴 전체 흐름 | pattern, 게스트 저장, 1개 대표 스테이지, 결과·해설 | D02 | 새로고침·재도전·다른 문제 복습까지 연결 |
| D04 나머지 7종 | 게임별 판정·수치·대표 콘텐츠·대체 조작 | D03 | 8종의 정답·오답·경계 자료 통과 |
| D05 계정과 기록 | 가입·로그인·선택 이메일·복구·병합·삭제 | D01,D03 | 실제 테스트 메일 수신, 원자적 복구, 중복 없는 병합 |
| D06 학습 콘텐츠 | 240개 목표별 스테이지 정의, 대체 문제, 해설·힌트 | D04 | 콘텐츠 검수표 전수 충족, 공개 버전 고정 |
| D07 공식 경쟁 | 대회 생성·참가권·서버 판정·순위·중단·취소 | D04,D05 | 중복 응시·위조 점수·재전송·시한 경계 검증 |
| D08 기록과 표현 | 조건별 성과·복습 추천·업적·연구소 UI | D05,D06 | 비교 조건 유지, 추천 선택권, 접근성 흐름 확인 |
| D09 제품 검증 | 실제 기기·사용자·보안·운영·성능 | D06,D07,D08 | 주요 장애 해결, 실행 증거·잔여 문제 목록 |
| D10 출시 준비 | 운영자 정보·도메인·메일·백업·공개 승인 | D09 | 출시 조건 충족 후 별도 게시 결정 |

D03의 작은 완결 흐름은 기반 검증용이며 최종 8종 출시 범위를 줄이지 않는다. D06의 콘텐츠 제작은 D04~D08과 병행 가능하다.

## 2. 콘텐츠 제작 작업표

게임마다 30개 스테이지 ID와 아래 항목을 작성한다. 단계 번호만 만들었다고 콘텐츠 완성으로 계산하지 않는다.

| 항목 | 필수 내용 |
| --- | --- |
| 목표 | 관찰할 수행, 제안할 전략, 선행 규칙 |
| 문제 | 수치·자극·배치·선택지·조건과 허용 답 형식 |
| 판정 자료 | 정답 또는 검증 조건, 경로 최적값, 코드 피드백 예시 |
| 교육 | 전략 힌트·문제 힌트·해설·대표 오답 피드백 |
| 반복 | 최초 묶음 및 최소3개 검수된 문제 묶음으로 구성된 대체 풀, 노출 식별 |
| 검수 | 해의 존재·유일성 또는 복수해 인정·가독성·조작·난도 점검 |
| 버전 | 작성·검수 상태, 공개 버전, 수정 사유 |

첫 구현에는 게임 상세 명세의 8개 대표 예시와 반례를 사용한다. 전체 콘텐츠와 대체 풀은 출시 게이트다.

## 4. 사용자·기기 검증

- 성인과 중장년·시니어 각각 최소 3명을 초기 형성 평가 대상으로 모집하는 것을 제안한다. 작은 표본은 학습 효과의 통계적 입증 자료가 아니다.
- 과제: 가입 없이 첫 게임 완료, 오답 해설 이해, 보충 연습, 기록 찾기, 가입 후 이어 하기, 이메일 연결, 공식 도전 조건 설명하기.
- 관찰: 도움 없이 완료 여부, 잘못 이해한 규칙, 오입력, 화면 글자, 실패 후 행동. 원인을 질문으로 확인하고 클릭 기록만으로 단정하지 않는다.
- 차단 문제: 핵심 조작 불가, 해설·정답 오류, 기록 유실, 계정 오연결, 응시 중복, 개인정보 노출. 해결 전 관련 기능 완료 처리 금지.
- 360/390/768/1280px, 확대200%, 키보드, 터치, 마우스, 동작 감소, 소리 끔 환경을 확인한다.
- 기억 자극·전환 시점은 실제 모바일과 PC에서 확인한다. 에뮬레이터 통과만으로 공식 타이밍 검증 완료라고 하지 않는다.

## 5. 운영·성능 초기 목표

- 일반 페이지의 핵심 콘텐츠 표시 2.5초 이내, 입력 처리 장기 멈춤 없음, 레이아웃 이동 최소화. 측정 기기·망·캐시 조건과 함께 보고한다.
- 대표 환경에서 API p95 500ms 이내를 초기 목표로 삼고, 동시 활성 50사용자와 공식 제출 요청 10건/초로 DB 병목을 점검한다. 목표 부하가 운영 수요 예측을 뜻하지는 않는다.
- 접근성 WCAG 2.2 AA의 적용 가능한 기준을 검사한다. 자동 검사 외 키보드·대체 입력·문구 이해 검토를 포함한다.
- 실패한 마이그레이션, 메일 장애, 콘텐츠 철회, 대회 취소, 개인정보 삭제·백업 복원 절차를 실제 시험한다.

## 6. 문서와 구현 완료의 구분

현재 완료: 제품·학습 방향 문서, 8종의 수치와 판정 기본안, 화면 흐름, 계정·데이터·경쟁 정책, 기술·API 계약, 개발 순서와 수용 기준, 8종 대표 문제.

현재 미완료: 앱 코드, 실행 환경의 의존성 설치, 실제 DB·메일·호스팅 연결, 240개 스테이지와 대체 풀의 제작·전수 검수, 사용자·기기·보안·성능 검증, 제품명·운영자 정보·공개 배포.

개발 착수에 필요한 기본 문서 묶음은 마련된 상태다. 제작 중 발견한 모호함은 해당 명세와 수용 기준을 함께 수정한다. 구현이 끝나도 출시 게이트를 통과하기 전까지 제품 완성이라고 보고하지 않는다.
